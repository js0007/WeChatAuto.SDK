Why WeChatAuto.SDK

绕开微信自动化的三个老大难

内存 Hook / 协议破解 / 数据库解密，极易触发风控封号，还易碎难维护。 WeChatAuto.SDK 用「模拟真人操作」这条正路，从架构上规避风险。

🛡️

安全合规 · 不 Hook 不破解

不改写微信进程内存、不加载第三方模块进微信进程、不解密数据库、不越权读取数据。所有能力通过 UI Automation（FlaUI UIA3）+ OCR 双引擎完成，远离封号与灰色地带。

🪄

强开 UI Tree

微信默认不公开 UI Tree 也能自动化。内置「强开 UI Tree」能力，微信升级后只需维护 UI 定位，而非整套逆向方案 —— 更稳、更干净。

🧵

专有 Action 线程

所有 UI 操作统一调度到同一条专用线程，监听任务受信号量约束、与发送互斥排队。多微信在线也不抢鼠标、不抢窗口、不互相打断。

🖥️

远程桌面 + 硬件级输入

适配 RDP 最小化挂起优化与会话转移，云服务器上稳定运行；键鼠模拟器在硬件底层发信号，输入与人手无异，有效降低被风控概率。

Integrations

两种方式，按需接入

内嵌方式

.NET / Windows 原生应用
  • 类型安全、能力最全、深度定制
  • 事件回调、低延迟、完整 API
  • 入口：WeAutomation.Initialize(…) → WeChatClient

HTTP WebAPI 方式

后端 / 云服务 · 跨语言 · 多系统共享
  • 语言无关、进程隔离、可远程

Quick Start

30 秒上手

C# · Program.cs
# 安装 SDK
# dotnet add package WeChatAuto4x.SDK

var sp = WeAutomation.Initialize(o => o.EnableOCR = true);
using var factory = sp.GetRequiredService<WeChatClientFactory>();
var client = factory.GetWeChatClient("你的微信名");
await client.SendMessage("好友昵称", "hello world!");
bash · 任意语言可调用
# 启动 Server 后，任何语言都能调用
curl http://localhost:5000/api/v1/clients

  -H "Content-Type: application/json" \
